# Skintel iOS — guide for AI agents

Native SwiftUI app, iOS 17+, Swift 6, strict concurrency `complete`. App target `Skintel`
(bundle `com.skintel.app`), scheme `Skintel`, plus local SPM package `SkintelCore`
(platform-independent models/logic/API — its tests also run on Linux via `swift test`).

## The one rule that matters

**There is no local compiler.** The developer has no Mac; the only build is Codemagic CI
(`ios-ci` workflow, ~6 min per run). The first-ever compile of this app surfaced four bugs
that all shared one cause: Swift written from memory instead of checked against the real
declarations. Before committing Swift, verify every member access, init call, and label
against the actual type in this repo. `grep` is free; a CI round-trip is not.

## Mistakes already made here — do not repeat them

1. **Name collisions with imported frameworks.** SkintelCore declares its own `Product`
   (a skincare product — `SkintelCore/Sources/SkintelCore/Models/Models.swift`). Files that
   also `import StoreKit` MUST qualify: `StoreKit.Product`, `StoreKit.Transaction`. If you
   add a new public type to SkintelCore, check it doesn't shadow a StoreKit / SwiftUI /
   Foundation name used elsewhere; if you add an `import`, re-check bare type names in that
   file.
2. **StoreKit JWS lives on the envelope.** `jwsRepresentation` is a member of
   `VerificationResult<Transaction>`, NOT of the unwrapped `Transaction`. When you
   `case .verified(let tx)`, keep the wrapper around if the server needs the signed payload
   (see `SubscriptionService.report(_:jws:)`).
3. **Persisted models are fragile.** `ScanStore.load()` (and similar `try?` decoders) drop
   the ENTIRE store file on any decode error. Any field added to a persisted struct
   (`StoredScan`, journal/products stores) must be optional or defaulted, or every existing
   user loses their data on update. Also: adding a field means updating every construction
   site *including tests* — grep for the init before you commit.
4. **Injectable clocks must actually be used.** `DateFormatting.relative(_:now:)` broke
   because `Calendar.isDateInToday` reads the wall clock and ignored the injected `now`.
   If a function takes `now:`/`date:` for testability, every branch must derive from it —
   no `isDateInToday`, `isDateInYesterday`, bare `Date()`, or `.now` inside.

## Project mechanics

- `Skintel.xcodeproj` is **generated by XcodeGen** from `project.yml`. Adding/removing/moving
  files requires regenerating (`xcodegen generate`) — but there is no Mac, so prefer editing
  existing files; if you must add a file, update `project.yml` AND note that the committed
  xcodeproj is stale until someone regenerates. (Sources are globbed from the `Skintel/`
  dir, so new files under existing source dirs are usually picked up at generate time only.)
- Info.plist and Skintel.entitlements are ALSO generated from `project.yml` — edit the
  `info:`/`entitlements:` blocks there, never the plists directly.
- `Config/Config.xcconfig` is gitignored; CI copies `Config.example.xcconfig` into place.
  The Supabase anon key in it is public by design (RLS). Real secrets never go in xcconfig.
- CI: `codemagic.yaml` at repo root. `ios-ci` = simulator build + SkintelTests +
  SkintelUITests + SkintelCore `swift test`, no signing. `ios-release` = TestFlight upload;
  needs the Codemagic App Store Connect integration (`skintel_app_store_connect`) and env
  group `ios_release` (`DEVELOPMENT_TEAM`, `APP_APPLE_ID`). Build numbers come from App
  Store Connect at build time — never hard-code `CURRENT_PROJECT_VERSION` bumps.
- Entitlement authority is the server: purchases only count after `/api/apple-verify`
  confirms the signed transaction. Never grant Pro client-side.
- IAP product ids (`com.skintel.app.pro.monthly` / `.pro.yearly` / `.founding`) must stay in
  sync between `SubscriptionService.ProductID` and `api/_apple.ts` `APPLE_PRODUCTS`.
